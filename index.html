GraphNKI: Agentic and Recursively Self-Improving Kernels for Graph and Sparse AI Workloads on AWS Trainium

Guimu Guo (PI), Department of Computer Science, Rowan University · Submitted to Amazon Research Awards, Build on Trainium, Fall 2026

Irregular sparse computation makes accelerator software expensive to build and hard to generalize. GraphNKI is a structure-aware agent that generates, verifies, profiles, and improves kernels written in the Neuron Kernel Interface (NKI) on AWS Trainium. Our hypothesis is that optimization conditioned on input structure and validated prior experience finds better kernels under a fixed search budget than structure-oblivious or stateless agents.

How GraphNKI works

Inner loop: generate, compile, verify, and repair a kernel for the current task. Outer loop: update retrieval rules and transformation policies across tasks, adopting an update only when it improves a held-out validation set without degrading correctness.

Aim 1

Generate, measure, repair

Structure descriptors (degree quantiles, segment skew, feature width) guide NKI transformations: tiling, buffering, layout, degree bucketing, fusion. Every candidate is compiled, checked, and timed under a fixed budget.

Aim 2

Improve across tasks

An optimization-trajectory graph links workloads, kernel variants, transformations, and outcomes. Versioned, reversible policy updates are compared against flat retrieval and a frozen-policy agent.

Aim 3

Verify correctness

References and final tests stay outside the agent's workspace. Exact checks for set and integer operators, declared tolerances for floating point, edge-case and metamorphic tests.

Expected outcomes and success criteria

These are the questions the project is designed to answer. They are targets, not measured results.
Criterion 1

Correctness

All released kernels pass the held-out correctness suite.

Criterion 2

Structure helps

Under matched budgets, GraphNKI achieves higher geometric-mean speedup over direct NKI baselines than a structure-oblivious agent on held-out workloads.

Criterion 3

Experience helps

With validated memory, GraphNKI reaches a fixed performance threshold in fewer evaluations than a frozen-policy agent.

Baselines include direct NKI implementations, available framework operations, a documented human-tuned implementation, and a generic coding agent. Agent comparisons share the base model, tools, examples, and search budget. We report correctness, latency distributions, geometric-mean speedup, time to threshold, tokens, accelerator hours, and preprocessing costs, including workloads where the approach does not help.

Timeline

  1. Months 1–3 · Baselines and feasibility. Operator contracts, baseline NKI kernels, held-out workloads, measurement harness. Release benchmark specifications.
  2. Months 4–6 · Agent optimization loop. Generation, verification, profiling, and repair. Structure-aware versus structure-oblivious comparison. Initial agent release.
  3. Months 7–9 · Recursive improvement. Trajectory retrieval, policy validation, versioned updates. Graph memory versus flat retrieval versus frozen policy. Trajectory release, including failed candidates.
  4. Months 10–12 · Integration and dissemination. End-to-end evaluation, PyTorch custom-operator packaging via torch-neuronx, documentation, and a research paper.
